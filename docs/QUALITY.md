# Relay 测试策略与验收标准

> 版本：0.1-draft · 2026-10-20 · 用于定义可验证的工程质量，不表示测试已执行。

## 1. 测试层次

| 类型 | 测什么 | 建议工具 |
| --- | --- | --- |
| 单元测试 | 路径类型、状态机、传输规划、冲突解析 | `cargo test`、内存测试替身 |
| 集成测试 | SFTP 读写、SSH 认证、Host Key、PTY 生命周期 | Docker OpenSSH 测试容器 |
| 故障注入 | 网络中断、权限变化、磁盘满、取消、竞争写入 | 网络隔离/故障代理、可控 FS |
| UI 测试 | 焦点、快捷键、尺寸变化、错误提示、终端切换 | Ratatui TestBackend + 手工实际终端 |
| 跨平台 | 原生路径、SSH Agent、终端输入兼容性 | Linux、Windows + WSL2、Windows、macOS |
| 安全检查 | 依赖漏洞、Host Key 变更、日志脱敏、控制序列 | cargo audit/deny 等适当工具 |

## 2. 推荐的端到端测试拓扑

```text
Local test runner (Relay)
     │
     ├─ OpenSSH-A (source)
     ├─ OpenSSH-B (target)
     └─ OpenSSH-C (changed key / auth error / proxy)
```

测试容器准备不同用户、不同目录权限、符号链接、不同大小的文件，并可通过网络隔离确保 A 和 B 无法互相发起 SSH 连接，但 Relay 分别能访问两者。

使用固定已知测试数据，不使用真实生产 SSH 凭据。可以通过文件散列在测试机上校验字节级一致性。

| ID | 用例 | 预期 |

## 4. 文件系统与传输回归矩阵

**路径和目录：**
- 含空格、中文、Unicode 组合字符、特殊字符的文件名；
- 空目录、嵌套目录、大量小文件、单个大文件；
- 远端 POSIX 绝对路径与本地 Windows 驱动器路径；
- 目标不存在、同名目录/文件、同源同目标、大小写敏感性差异；
- 符号链接、目录环和指向目标目录之外的链接；
- 没有读取权限、没有写入权限、磁盘空间不足。

**传输生命周期：**
- 成功复制后内容和可声明的元数据匹配；
- 传输开始前发现旧目标且用户选择 Cancel / Skip / Overwrite；
- 传输中按取消，未提交临时文件处理符合策略；
- 复制过程中网络中断；重新连接后不会把部分文件算成功；
- 两个任务同时尝试写同一目标，队列能冲突检测；
- 来源在传输过程中变化：必须识别或至少明确不保证快照语义，不可静默声明强一致；
- 服务器不支持安全 rename/高级扩展：采取明确的降级或拒绝。

**完整性级别：**
- Basic = writer 完成 + 目标元数据核对；不等于散列一致。
- Strong (Later) = 用可信路径计算并比较源/目标散列；需要声明算法、远端读取和额外 IO 成本。
- 测试环境对关键数据使用散列比对，但产品 UI 只显示实际执行过的验证级别。

## 5. UI 与 PTY 回归

- Terminal Input 模式所有未保留按键正确转发远端；
- `Esc`、`Ctrl+C`、`Ctrl+P` 及方向键在 `vim` 中有正确语义；
- Relay Control 模式各界面可完全由键盘完成必要操作；
- 宿主终端对 F12 或其他候选逃逸键可能拦截：需要记录环境并提供 fallback；
- 80×24、120×40、窄列窗口和 resize 中途不 panic；
- 长耗时连接、扫描、复制不会卡住绘制与输入；
- ANSI/OSC 序列和恶意文件名不会引起本地命令执行、非预期剪贴板读取/写入。

## 6. Tailscale 兼容性

测试前置条件：本机 Tailscale 服务已正确连接，Tailnet 路由/ACL 允许流量，目标有可用 SSH 服务。

| 情景 | 预期 |
| --- | --- |
| Tailnet IP + 常规 SSHD | 可以通过 russh/SFTP 连接 |
| MagicDNS 可解析 | 连接行为等同普通域名 |
| 本机没有 Tailnet 路由 | 报告网络不可达，不谎称认证失败 |
| Tailnet ACL 禁止访问 | 连接失败，有可诊断错误 |
| Host Key 变化 | 即使走 Tailscale，也必须阻止连接 |
| Windows Tailscale + WSL2 Relay | 分别验证 Windows 与 WSL2 路由和 DNS |

Tailscale SSH 认证模式不作为普通 SSH over Tailscale 的通过条件。

## 7. 性能和资源基线

P0 首先记录测量值，再设置可执行的阈值。当前先采用**设计不变量**而非随意承诺 MB/s：

1. 单文件流式传输使用固定上限的读写缓冲，内存不应随文件总大小线性增加。
2. 文件传输期间 UI 事件循环不执行阻塞网络读写。
3. 并发任务数必须有上限，且针对单 Host 限流/连接数可配置。
4. 任务进度事件节流，避免每个网络分块导致全屏刷新。
5. 拆分“文件数进度”与“已知字节进度”；未知总量时使用不确定状态。
6. 记录 100 MiB、1 GiB 测试文件与大量小文件的吞吐、CPU、峰值 RSS 和终端输入延迟，作为基线；不固定不具备测量依据的速度承诺。
