# Relay 安全设计与威胁模型

> 版本：0.2-draft · 2026-10-20 · 属于实现约束，MVP 不能以“之后再补”为由忽略关键项。

## 1. 信任边界

Relay 是本机运行的 SSH 客户端和文件操作工具，不是 VPN、认证中心或远端管理守护进程。需要明确区分：

- **本机可信输入**：用户显式操作、受限配置、系统 SSH Agent。
- **不可信远端**：SSH 主机在首次信任前不可信；远程文件名、元数据、Shell 输出、VT 控制序列及错误消息均可能是恶意数据。
- **网络链路**：公共网络、跳板机、Tailscale 网络只是载体，**网络可达不等于 SSH 主机身份可信**。
- **文件操作目的地**：可能有旧文件、同名目录、符号链接、权限变化及磁盘不足等情况。

安全目标：身份不被无声冒用、用户已有数据不被无提示破坏、机密凭证不通过日志/UI/远端传输泄漏。

## 2. SSH 主机密钥校验（必须）

1. 连接服务器时校验 Host Key，尽量遵循 OpenSSH 已知主机的信任语义。
2. 首次遇到未信任的主机时展示主机名、地址、密钥算法和 SHA-256 指纹，并要求用户明确确认。不得自动接受。
3. 已知主机密钥变化时拒绝连接，显示可能的原因和校验指导。不能自动覆盖旧信任记录。
4. 同一主机可能使用多个别名、端口或经过代理，映射到可信记录时必须谨慎，不能因为别名不同就绕过已知风险。
5. 不允许生产连接使用“总是接受所有 Host Key”的代码路径，包括调试开关默认关闭并不可由未认证远端启用。
6. OpenSSH 后备模式与 russh 原生模式应保持同等的主机身份校验要求。
7. **信任判定由 Relay 自行实现**（russh 自带的 known_hosts 函数不支持通配符、`@revoked`、全局文件，且把“已知其他算法密钥”当作未知主机）。规则见 [架构 §5.3](ARCHITECTURE.md#53-主机密钥信任自研模块)：
   - `@revoked` 命中即拒绝；
   - 仅存在其他算法的已知密钥时，按高风险变化提示，而不是当作首次连接；
   - 信任查找按 `HostKeyAlias` 或实际连接的主机名 + 端口，**不按 Relay 别名**，避免换个别名就绕过已知记录。
8. SSH 配置只能让校验**更严格**：`StrictHostKeyChecking no/accept-new`、`UserKnownHostsFile /dev/null` 不会让 Relay 跳过确认，并在主机详情中提示。
9. 新信任默认写入 Relay 自有信任库（0600）；从不修改、删除已有 known_hosts 条目。
10. ProxyJump（0.2）中的每一跳都独立执行完整主机校验。

测试包括新主机、已知主机、哈希条目、通配符、`@revoked`、密钥变化、算法变化、不同端口、代理和不可信服务器。

## 3. 认证凭据

- 优先使用 OpenSSH 私钥文件或系统 SSH Agent，避免把密钥复制到 Relay 自有存储。
- 密码可交互输入，输入隐藏，不写明文配置和日志；如需要长期保存，必须使用 OS Keychain/凭证管理器，并明确用户授权。
- 默认禁用 Agent Forwarding；仅在用户了解风险后针对指定主机显式启用。
- 不把远端 A 的登录凭据转发给远端 B 以实现直传；后期远端直传需要独立的认证、用户授权与威胁评估。
- 对认证失败提示保留必要原因，但避免输出敏感凭证、完整令牌和不必要的密钥路径。
- 密码与私钥口令仅在内存中短暂持有（`secrecy`/`zeroize`），认证完成即清零，不进入日志、崩溃报告或 Debug 输出。
- Prompt Broker 的请求必须标明来源主机与原因（“prod 请求密码”），防止在多主机并发连接时把 A 的密码输入给 B。

### 3.1 本地配置可执行性

SSH 配置中有会执行本地命令的指令：`ProxyCommand`、`LocalCommand`、`Match exec`、`KnownHostsCommand`。

- MVP 不执行 `ProxyCommand`、`LocalCommand`、`KnownHostsCommand`，明确提示不支持；
- 使用 `ssh -G` 解析配置时 OpenSSH 可能执行 `Match exec`——这与用户直接运行 `ssh` 等价，只在用户主动连接时触发，并提供关闭 `ssh -G` 的选项；
- 远端返回的任何内容都不会进入本地命令执行路径。

## 4. 安全文件操作

| 风险 | 最低控制 |
| --- | --- |
| 覆盖已有文件 | 事先读取目标状态、明确冲突策略、优先临时目标写入 |
| 空目标路径 / 同源同目标 | 复制前拒绝；避免错误拼接导致覆盖源文件 |
| 多任务同时写入同一目标 | 调度器按规范化目标路径排他/冲突提示 |
| 断电 / 网络中断 | 任务不得标为 Completed；保留可诊断状态 |
| 删除目录 | 明确显示路径和递归范围，删除前确认 |
| 软链接与目录环 | 默认不递归跟随目录符号链接；拒绝越界危险路径 |
| 路径分隔符及编码 | Windows 本地与 POSIX 远端路径分开表示 |
| 目标在操作期间变化 | 在提交前重新确认元数据/冲突条件；尽可能避免 TOCTOU |
| 权限 / 时间戳 | 以安全的最小权限创建临时文件，按可用能力保留元数据 |
| 校验失败 | 报告具体校验级别，不将大小一致声称为字节完全一致 |
| 恶意远端文件名 | 丢弃 `.`、`..`、空名、含 `/` 或 NUL 的目录项；下载时拒绝会在本机越界的名称 |
| 非 UTF-8 / 有损解码名称 | 内部按字节保存；在字节路径可用前，含 U+FFFD 的名称禁止写、删、改名、复制 |
| Windows 本地非法名 | 保留名、`<>:"\|?*`、结尾点或空格、大小写冲突：拒绝并报告，不自动改名 |
| 覆盖不具备原子性 | 远端无 `posix-rename@openssh.com` 时 MVP 拒绝覆盖，绝不“先删旧文件再改名” |
| 特权权限位 | 复制时去除 setuid / setgid / sticky 位；不复制属主 |
| 源文件在传输中变化 | 结束时重新 stat，变化则该文件失败，不声称快照一致 |

### 4.1 文件写入提交协议（推荐）

```text
preflight → allocate unique temporary target
         → stream write (bounded buffer)
         → writer flush / finish
         → verify (level determined by capabilities)
         → safe commit/rename
         → mark complete
```

远程 SFTP 服务器对覆盖重命名、原子性及元数据支持各异；若无法保证目标文件安全，必须改变策略、提示用户或拒绝操作，不允许直接假设 rename 是原子的。具体步骤见 [架构 §7.3](ARCHITECTURE.md#73-提交协议)：临时文件以 `create_new` + 0600 创建；目标不存在时用不替换的 rename（同时防止提交瞬间的竞争）；覆盖只用原子替换。

## 5. 终端输出的特殊风险

SSH PTY 输出包含 ANSI/VT 控制序列、OSC 超链接及可能触发外层终端行为的控制消息。它们是**远端不可信输入**。

- VT Parser 不应该让远端消息直接执行本地系统命令；
- 对 OSC 52 剪贴板读写等敏感终端能力制定明确策略，默认不授予远端静默控制本地剪贴板；
- 文件名、错误消息、主机别名要按文本渲染，过滤危险控制字符；
- 交互式 Terminal Input 模式应尽可能忠实转发用户按键，但不能把远端内容混入 Relay 命令解释器；
- 不自动把拖入/粘贴内容作为 Shell 命令执行；
- **括号粘贴注入**：远端启用括号粘贴时，粘贴内容中的 `ESC[201~` 必须剔除，防止提前结束粘贴模式后执行后续内容；远端未启用括号粘贴时，多行粘贴可配置为先确认；
- **查询应答**：对 DA/DSR 等设备查询的应答只由终端仿真状态生成，不回显任何远端可控内容（避免“回显注入”类攻击）；
- Relay 自己向 PTY 发送的命令（如“在此目录打开终端”的 `cd`）必须做 shell 转义，路径含控制字符时不发送；
- 滚动缓冲有上限，防止恶意输出耗尽内存。

## 6. Tailscale 安全边界

- 普通 SSH over Tailscale 仍需 SSH Host Key 验证和 SSH 用户认证；
- Tailnet IP、MagicDNS 可达，并不代表拥有 SSH 服务的访问授权；
- 不自动修改 Tailscale ACL、grants、路由、SSH policy 或端点防火墙；
- Tailscale SSH 的身份授权由其自身系统负责，必须另行实现与验证；不能用普通 SSH 的凭据模型去假定它等价；
- 读取 `tailscale status --json` 作为设备发现时，不应上传 Tailnet 拓扑信息到外部服务。

## 7. 日志与本地隐私

日志应包含任务 ID、脱敏的来源/目标、阶段、耗时、错误类别、字节数。不记录密码、私钥内容、SSH Agent 响应、敏感命令输入和完整 Shell 会话内容（除非用户明确选择录制，且另设保护）。

建议启用结构化日志、默认最小级别，并明确调试日志的敏感信息风险。异常报告默认不上报服务器；应用不要求注册登录。

Relay 的本地文件（`config.toml`、`hosts.toml`、Relay 信任库）以 0600 创建，日志目录 0700；启动时发现权限过宽给出警告。panic 时先恢复终端状态（退出 raw mode / 备用屏幕），再写入不含秘密的崩溃信息。

## 8. 发布前安全验收

- [ ] Host Key 首次确认、已知密钥变化、算法变化、`@revoked` 和代理场景得到实际测试
- [ ] 密码与密钥不写入日志/明文配置
- [ ] 覆盖目标文件前完整展示主机与路径
- [ ] 网络中断、取消及并发冲突不静默破坏已有文件
- [ ] OSC/控制字符、文件名渲染、括号粘贴注入不存在已知危险路径
- [ ] 恶意 SFTP 服务器返回的 `..`、含 `/` 的名称和非 UTF-8 名称被正确拒绝
- [ ] 依赖安全扫描及许可证检查通过
- [ ] CLI 与 TUI 的文件操作适用相同安全默认值
