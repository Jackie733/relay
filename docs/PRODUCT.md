# Relay 产品需求文档（PRD）

> 文档版本：0.2-draft · 日期：2026-10-20 · 状态：设计基线（尚未实现）

## 1. 产品概述

Relay 是一个使用 Rust 开发、以键盘为主要交互方式的多主机 SSH TUI 工作台。它把 **交互式 SSH 终端、SSH 主机管理、双栏文件浏览、多主机文件传输及后台任务队列** 放在统一的本地应用中。

**一句话定位：** 在一个终端应用里连接任意 SSH 主机，并在不中断 Shell 工作的情况下浏览和传输主机间的文件。

核心区别不是“又一个 SFTP 客户端”，而是将 **主机、文件端点、终端会话、传输任务相互解耦**，让多台服务器构成统一的可操作工作空间。

### 1.1 目标用户

| 用户 | 典型场景 | 优先级 |
| --- | --- | --- |
| 独立开发者 / 全栈工程师 | 本机、开发机、云服务器间调试与发布 | 最高 |
| 使用多台 Linux 服务器的运维人员 | 多会话、查看日志、传送备份 | 高 |
| 自托管 / NAS 用户 | 通过内网或 Tailscale 管理设备 | 高 |
| 复杂批量运维团队 | 集中策略、审计、多人共享 | 非首期目标 |

### 1.2 需要解决的问题

1. SSH Shell 和文件管理器之间来回切换，操作上下文容易丢失。
2. 远程 A 到远程 B 的文件复制通常需要另开终端或手工组合 scp/rsync 命令。
3. 长时间传输时需要同时继续操作终端、查看文件、处理其他任务。
4. OpenSSH、跳板机、Tailscale 地址与多个连接配置分散，管理成本高。
5. 已有 TUI 工具在“真正的 PTY + 独立后台队列 + 任意主机文件面板”三者结合方面仍存在体验空间。

### 1.3 产品原则

- **SSH First**：早期仅以 SSH/SFTP 为核心；不做 FTP、S3、SMB 统一客户端。
- **TUI First**：完整键盘操作；可用的鼠标与拖入文件只是增强。
- **Task First**：传输任务独立于 UI 和当前 SSH 终端；MVP 中 Relay 进程退出即中断任务（见 [架构 §7.6](ARCHITECTURE.md#76-后台语义与退出)）。
- **Safe by Default**：主机密钥验证、覆盖保护、错误反馈必须优先于便利。
- **Local First / Agentless**：无 Relay 云账户、无 Relay 服务器端守护进程。
- **Incremental**：以可测试的最小链路交付，避免同时实现过多协议和周边功能。

## 2. 核心使用场景

### UC-01 首次连接服务器

用户启动 Relay → 进入 Hosts 工作空间，看到 SSH 配置中的别名与已保存主机（或手工填写连接参数）→ 首次确认可信服务器指纹 → 使用 SSH 密钥/Agent/密码登录 → 打开交互式 Shell。

**成功标准**：主机可保存为连接条目；SSH Host Key 变化时拒绝继续连接；登录失败可区分网络、认证和主机验证问题；配置中不支持的指令（如 ProxyCommand）被明确提示，而不是静默忽略。

### UC-02 终端与文件面板协作

用户在 Server A 中运行 `vim` / `htop`，切换至文件视图查看 `/var/log`，再返回原会话；终端不被重新创建。

**成功标准**：PTY 输入输出、终端尺寸变化、焦点切换及文件浏览互不阻塞。

### UC-03 本地与远程文件互传

用户将左侧设置为 Local，右侧设置为 Server A，选择文件后进行复制；展示进度、目的地、覆盖确认和失败状态。

**成功标准**：不会在未经确认的情况下覆盖现有文件；任务取消后不会将部分文件误标记为成功；覆盖时旧文件在新文件提交前始终完整。

### UC-04 两台远程主机之间传输

左右面板分别设置为 Server A 和 Server B；用户选择文件/目录并传输。V0.1 使用 **本机内存流式中继**，不要求 A 与 B 直接互通。

**成功标准**：目标文件内容正确；一般 SFTP 文件的传输内存不随文件大小线性增长；远程 Shell 可继续使用。数据仍通过 Relay 本机的网络，不承诺“远端直连”。

### UC-05 Tailscale 私有网络

用户在本机已有 Tailscale 路由时，通过 Tailnet IP 或 MagicDNS 名称连接目标 SSH 服务。首期按普通 SSH over Tailscale 处理。

**成功标准**：如果本机可通过标准 SSH 到达目标且认证有效，Relay 能复用同样的网络连通性；不要求在 Relay 内实现 VPN 或节点发现。

## 3. 功能需求

约定：P0 = 技术可行性验证，MVP = 0.1 首个实用版本，Later = 延后。编号是稳定的需求标识。

| ID | 功能 | 阶段 | 说明 |
| --- | --- | --- | --- |
| FR-01 | 主机清单 | MVP | 列出 SSH Config 别名、手动添加/编辑/删除保存的主机、搜索与最近使用 |
| FR-02 | SSH 身份认证 | MVP | SSH Agent、密钥文件（含口令）、keyboard-interactive、密码；不保存密码 |
| FR-03 | Host Key 校验 | P0 | 兼容 OpenSSH known_hosts 语义（哈希、通配符、`@revoked`）；首次显式信任，变化时阻止连接 |
| FR-04 | 真实 SSH PTY | P0 | 持续双向字节流、按远端模式编码按键、尺寸同步、VT 渲染 |
| FR-05 | 多终端 Tab | MVP | 每个会话独立焦点与状态，退出后状态明确 |
| FR-06 | 双栏文件浏览 | MVP | 每栏可独立选择 Local / Remote Host 和目录 |
| FR-07 | 基础文件操作 | MVP | 浏览、属性查看、创建目录、重命名、删除、上传与下载 |
| FR-08 | 跨远程主机复制 | P0 | A → 本机流式中继 → B，优先 SFTP |
| FR-09 | 全局传输任务队列 | MVP | 进度、取消、错误、受控并发和失败重试 |
| FR-10 | 覆盖与冲突策略 | MVP | 创建任务时询问；支持跳过、覆盖、应用到全部；无法原子覆盖时拒绝 |
| FR-11 | Tailscale 地址访问 | MVP | Tailnet IP / MagicDNS 作为普通 HostName，依赖操作系统路由；只需验证，无专门代码 |
| FR-12 | OpenSSH 配置兼容 | MVP | 优先通过 `ssh -G` 解析有效配置；支持指令见架构 §5.1，不支持的指令明确提示 |
| FR-13 | CLI 复制子命令 | Later (0.2) | 与 TUI 复用相同传输引擎 |
| FR-14 | 断点续传 / 任务持久化 | Later (0.2) | 先定义恢复规则，避免误续传 |
| FR-15 | 自动发现 Tailnet 节点 | Later | 可选本机 `tailscale status --json` 集成 |
| FR-16 | Tailscale SSH 身份模式 | Later | 与“通过 Tailscale 网络使用普通 SSH”区分 |
| FR-17 | 文件拖入路径上传 | Later | 依赖终端模拟器是否会传入本地路径 |
| FR-18 | 远端 A → B 直接传输 | Later | A 必须能够访问 B，凭证授权与监控另设 |
| FR-19 | 目录差异与增量同步 | Later | 不纳入 MVP |
| FR-20 | GUI / 云端协作 | 不计划 | 不改变纯本地 TUI 核心定位 |
| FR-21 | 配置与快捷键 | MVP | 配置文件；至少逃逸键、并发上限、OSC 52 策略可配置 |
| FR-22 | 诊断日志 | MVP | 结构化、脱敏日志文件，便于报告问题 |
| FR-23 | ProxyJump 跳板机 | 0.2 | 单跳/多跳，跳板机同样执行主机校验；需求度高，优先级靠前 |
| FR-24 | 文本预览 / 远程编辑 | Later | 只读预览（限大小）；用本地 `$EDITOR` 编辑后回传 |

### 3.1 MVP 具体边界

必须包含：至少 2 台远程主机与本机、多个持续运行的 SSH PTY Tab、独立双栏文件管理、任意来源/目标 SFTP 文件复制、可见后台任务与取消、基本覆盖保护、可信主机身份校验。

不承诺：真正“所有 OpenSSH 配置零差异兼容”、ProxyJump/ProxyCommand、断点续传、应用退出后继续传输、Tailscale SSH 身份接管、跨协议复制、原生桌面拖放、文件预览/编辑、终端鼠标转发、完整 WinSCP 功能集。

### 3.2 文件行为规则

- 文件来源/目标由 **Location（本机或 HostId）+ 路径** 唯一描述；不通过左右面板角色推导。
- 复制前检查同源同目标、目录复制到自身内部、目标重名、源文件类型与目标权限。
- 冲突在**创建任务时**一次性决定；运行中目标被他人创建时该文件失败，不弹窗阻塞后台任务。
- 写入总是先到同目录临时文件，成功后改名提交；覆盖已有文件必须使用原子替换（远端需 `posix-rename@openssh.com`），不支持时 MVP 拒绝覆盖。
- 目录递归复制中的符号链接、FIFO、设备文件默认跳过并在结果中列出；用户直接选中的文件符号链接复制其目标内容。
- 文件名按原始字节处理；无法安全表示的名称（非 UTF-8 等）禁止写操作；写往 Windows 时非法名称拒绝并报告，不自动改名。
- 用户取消/连接丢失后，任务应明确呈现为 Cancelled / Interrupted / Failed，而不是 Completed；部分条目失败为 CompletedWithIssues。
- 文件大小、时间戳一致不能替代强校验；不同级别的完整性验证需要明确展示。

## 4. 非功能需求

| 维度 | 约束 |
| --- | --- |
| 安全 | 严格校验主机密钥；敏感信息不写入日志；默认关闭 Agent Forwarding |
| 响应 | 传输期间键盘输入不应因阻塞式 SFTP 读写而卡住；正式阈值见 QUALITY |
| 内存 | 流式文件复制使用有界缓冲，不随文件大小线性增长 |
| 可恢复 | 网络、主机验证、认证错误必须可区分；磁盘空间不足等远端错误尽力区分（SFTP v3 状态码有限，见架构 §11） |
| 可移植 | 优先 Linux / WSL2；随后原生 Windows / macOS |
| 可维护 | 核心与 TUI 解耦，异步任务不持有 UI 组件 |
| 可观测 | 任务 ID、来源、目标、字节数、进度和失败原因可追踪（脱敏） |

## 5. 版本验收

**P0 技术门槛：**
- 已验证的 Host Key 连接；变更/未知指纹得到正确处理；
- 远程 `vim`、`htop` 能与 TUI 共存；
- A → B SFTP 流式复制成功，转发过程有界缓冲；
- 文件复制期间终端能够持续输入输出。

**MVP 产品门槛：**
- 连接、终端、文件浏览、跨机复制及任务队列形成一条可重复的真实工作流；
- 常见路径覆盖、权限错误、网络中断不会静默破坏已存在文件；
- 面板、终端和传输均具备键盘可达路径与基本错误提示；
- 按 [测试与验收](QUALITY.md) 的核心场景通过。

## 6. 已确认决策与待验证问题

### 6.1 已确认决策（2026-10-20）

- 新信任默认写入 Relay 自有 `<config>/relay/known_hosts`（Linux 默认 `~/.config/relay/known_hosts`，遵循平台配置目录约定）；同时读取 OpenSSH 用户级、系统级信任记录，Relay 记录不能绕过冲突或撤销。
- 服务器不支持原子覆盖时，MVP 拒绝覆盖并保留旧文件；用户可改名另存。
- ProxyJump 保留在 0.2。仅当自用核心场景或首批试用用户因此无法连接日常目标主机时重新评估；若提前，0.1 只增加单跳，多跳和 ProxyCommand 仍延后。
- SFTP 优先自研精简 v3 原型，复用 russh 的 SSH 层；P0 Gate 后定案，改造 russh-sftp 为备选。

### 6.2 待验证问题

- 单条 SSH 连接复用终端与文件传输 Channel 时，终端延迟是否可接受？（P0-04）
- 自研精简 SFTP v3 能否满足字节路径、原子覆盖、异常处理及有界资源要求？（P0-03）
- 逃逸键默认值与后备键在各终端模拟器中的兼容性？（P0-02）
- WSL2 中如何使用 Windows 侧 SSH Agent？硬件密钥与证书何时支持？
- 收集首批用户的跳板机连接阻断反馈，按 §6.1 的条件重新评估排期。
